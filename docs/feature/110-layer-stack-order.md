## 조사 결과 (Findings)

- 교차 검증 게이트: ①/② 없음(메모 형태라 원 스토리 섹션은 이번에 작성), 디자인 파일 없음(n/a). 통과.
- 원스톱 쌓임 순서(2026-11-23, `vmap.getLayers()` 직접 확인, 바닥 → 위): 경계구역, 관제권, 비행금지, 비행장교통, 비행제한, UA, 경량항공기, 읍면동, 위험, 사전협의, 장애물, 임시비행금지, `lt_c_uo301`, 국립자연공원, 드론시범사업, 항만. 비행금지가 비행제한·UA보다 아래에 깔린다.
- ③ 우리 앱은 `constants.ts`의 `ZONE_TYPES` 한 순서를 WMS 타일 쌓임과 클릭 겹침 판정에 함께 쓴다(`AirspaceWmsLayer.tsx` 슬롯 부착 순서, `wmsTilesets.ts` 슬롯 분할).
- ③ 폴리곤은 쌓임을 레벨별 zIndex(금지 3, 제한 2, 가능 1)로만 정한다(`AirspacePolygon.tsx`). 위험구역이 #105에서 제한 레벨로 내려가 레벨만으로는 순서를 못 정한다.
- ③ 클릭 오버레이는 클릭 지점 스피너(`AirspaceClickPending.tsx`)만 보이다가 구역이 확정되면 카드가 뜬다(`MapView.tsx:153-163`).
- 미확인: VWorld WMS가 한 `LAYERS` 안에서 앞 레이어를 아래에 그리는지, 폴리곤 종류별 zIndex가 같은 레벨에서 의도대로 적용되는지(02 착수 때 확인).

- 확인: VWorld WMS는 `LAYERS`의 앞 레이어를 아래, 뒤 레이어를 위에 그린다(같은 BBOX에 두 순서로 요청해 비교). 스토리의 확인 필요 사항 중 `LAYERS` 순서 동작이 해소됨.
