# 스펙: 국토부 쌓임 순서 상수 분리 (#112, 스토리 #110)

## 배경/목적

겹친 구역의 색 쌓임은 국토부 원스톱과 같아야 한다. 원스톱 지도 객체(`vmap.getLayers()`, 2026-11-23 확인)에서
그려지는 순서를 읽어 보니 비행금지가 비행제한·UA보다 아래에 깔린다. 반면 우리 `ZONE_TYPES` 배열 순서는
클릭 겹침 판정(위험도 순, 비행금지 최상위)과 WMS 쌓임에 함께 쓰인다. 두 순서의 의미가 다르므로 쌓임용 순서를
별도 상수로 분리한다. 적용(WMS·폴리곤)은 #113에서 한다.

## 입력

- **`LAYER_STACK_ORDER`**: 우리 12종 typename을 바닥 → 위 순서로 나열한 상수 (`constants.ts`).

## 기대 동작

- [ ] 12종 typename을 모두 한 번씩 포함한다(`ALL_ZONE_TYPENAMES`와 같은 집합).
- [ ] 원스톱 순서를 따른다: 경계구역 → 관제권 → 비행금지 → 비행장교통 → 비행제한 → (군작전구역, 임시) → UA → 경량항공기 → 위험 → 임시비행금지 → 국립자연공원 → 드론시범사업.
- [ ] 비행금지가 비행제한과 UA보다 아래에 있다(원스톱과 같은 동작).
- [ ] 클릭 판정 순서(`ALL_ZONE_TYPENAMES`, 비행금지 최상위)는 그대로다. 두 순서는 서로 다르다.

## 엣지케이스

- [ ] 군작전구역(`lt_c_aismoac`)은 원스톱 레이어에 없어 위치가 미정이다. 비행제한구역 바로 위에 임시로 두고 주석으로 확인 필요를 표시한다.
- [ ] 원스톱의 범위 밖 레이어(`lt_c_aispca`, `lt_c_aisobls`, `lt_c_uo301`, `lt_c_ademd`, `lt_c_aisport`)는 순서에서 제외한다.

## 범위 밖

- WMS·폴리곤에 순서 적용 (#113)
- 클릭 오버레이 UI (#114)

# 스펙: WMS·폴리곤에 쌓임 순서 적용 (#113, 스토리 #110)

## 배경/목적

#112에서 만든 `LAYER_STACK_ORDER`를 WMS 모드와 폴리곤 모드의 색 쌓임에 적용한다. 클릭 겹침 판정(`ZONE_TYPES`,
비행금지 최상위)은 바꾸지 않는다.

## 확인된 사실 (2026-11-23, VWorld 실측)

- WMS `LAYERS=a,b`는 앞 레이어(a)를 아래에, 뒤 레이어(b)를 위에 그린다. 같은 BBOX에서 `prhc,resc`는 비행제한(초록 빗금)이
  비행금지 분홍 채움을 덮었고, `resc,prhc`는 분홍 채움이 위에 보였다.
- 카카오 오버레이는 나중에 `addOverlayMapTypeId`한 것이 위에 그려진다.

## 입력

- **`getVisibleTypenames(visibility)`**: 켜진 typename을 `LAYER_STACK_ORDER` 순서(바닥 → 위)로 반환한다.
- **`STACK_Z_INDEX_BY_LABEL`**: 구역 종류 라벨 → 폴리곤 zIndex(1~12).

## 기대 동작

- [ ] `getVisibleTypenames`는 필터 상태의 키 순서와 무관하게 쌓임 순서로 반환한다.
- [ ] WMS 슬롯(요청당 4개)은 그 순서를 이어서 채우고, 슬롯 0부터 오버레이로 추가한다(앞 슬롯이 아래).
- [ ] 슬롯 안 `LAYERS`도 앞이 아래다.
- [ ] 폴리곤 zIndex는 `STACK_Z_INDEX_BY_LABEL`(종류별)이다. 알 수 없는 종류는 레벨 zIndex로 대신한다.
- [ ] 폴리곤 구역번호 라벨의 zIndex는 레벨 기준 그대로다(안내 카드 zIndex 10 아래 유지).
- [ ] 클릭 판정 순서(`ALL_ZONE_TYPENAMES`)와 태그 순서는 그대로다.

## 엣지케이스

- [ ] 일부 구역을 꺼도 남은 구역의 상대 순서가 유지된다.
- [ ] 전부 꺼지면 오버레이를 붙이지 않는다(기존 동작).
